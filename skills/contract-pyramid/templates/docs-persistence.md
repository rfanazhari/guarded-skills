# Persistence

`{{Aggregate}}` has two adapters behind one port.

1. **Memory.** Process-local, safe for concurrent use, no external database. Default for local run and unit tests.
2. **Durable.** A relational store selected by configuration. Schema is created by that adapter when the process starts. There is no separate migration history and no down migration. Say that in the runbook.

## Identity and time

- Primary key: a string id generated by the application.
- `created_at` and `updated_at` are set by the application clock passed into the use case.
- Uniqueness: the id is unique. Creating the same id again returns the conflict sentinel.

## Delete

Default: hard delete. The row or map entry is removed. A missing id returns the not-found sentinel.

Write a soft-delete section only when the user asked for it. That section names the timestamp that is set and states that subsequent reads do not return the row. Both adapters implement that behavior. Do not add a `deleted_at` column for a hard delete.

## Columns for the sample aggregate

| Column | Rule |
| :--- | :--- |
| id | string primary key |
| title | required text, 1..255 |
| description | optional text |
| status | required text, default the starting status |
| created_at | timestamp, required |
| updated_at | timestamp, required |

Do not add a column the entity does not have.

## Illustration

```sql
CREATE TABLE {{table}} (
    id VARCHAR(36) PRIMARY KEY,
    title VARCHAR(255) NOT NULL,
    description TEXT,
    status VARCHAR(32) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL
);
```

The illustration uses a common relational dialect. The binding rules are the rows above, not the dialect.
